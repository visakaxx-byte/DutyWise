# bparty-pipeline（乙方清关流水线）交接文档

## 1. 项目定位

bparty-pipeline 是 DutyWise 清关优化系统的一个**独立子项目**，专门复现乙方（物流公司）的人工操作模式。核心目标：输入 Excel 清单 → 自动品名归类 → 跨章 HS 优化 → 低申报调整 → 输出清关文件。

与主后端（:8000）不同，这个子项目关注的是**策略层面**的操作，而不是简单的字段映射和数据提取。

## 2. 启动方式与端口

| 服务 | 端口 | 启动命令 | 说明 |
|------|------|----------|------|
| 主后端 | 8000 | `cd backend && python main.py` | 基础清关服务 |
| bparty-pipeline | 8001 | `cd bparty-pipeline && python3 app.py` | **本次重点** |
| 前端 | 3001 | `cd frontend && npx vite --port 3001` | React + Ant Design |

### sys.path 注入机制

`app.py` 和 `pipeline.py` 通过 `sys.path.insert` 复用 `backend/` 下的服务模块：
```python
sys.path.insert(0, str(_BACKEND_ROOT))  # app.* → backend/app/*
sys.path.insert(0, str(_HERE))           # strategy.*, pipeline
```
注意 `_BACKEND_ROOT` 必须在 `_HERE` 之前，否则 `bparty-pipeline/app.py` 会遮蔽 `backend/app/` 包。

## 4. 7步流水线流程

`pipeline.py` → `run_pipeline()` 包含以下步骤：

| 步骤 | 模块 | 说明 |
|------|------|------|
| [1/7] 解析 | `DocumentParser` | 提取 Excel 所有 sheet，自动检测表头行 |
| [2/7] 映射 | `FieldMapper` | 将任意列名映射到 14 个标准字段 |
| [3/7] 查税率 | `TaxRateCrawler` | 通过网络爬虫查询 HS 编码对应税率 |
| [4/7] 归类 | `ProductClassifier` | 关键词匹配改名 + HS 赋值 + 同类合并 |
| [5/7] 优化 | `CrossChapterOptimizer` | 全量搜索更低税率 HS 编码 |
| [6/7] 低申报 | `DevaluationStrategy` | 统一价格乘数压降 + 总价封顶 |
| [7/7] 生成 | `FileGenerator` | 写入 14 列标准模板输出 xlsx |

### 14 个标准输出列

`中文品名 | 英文品名 | 商品编码 | 材质 | 用途 | 箱数 | 数量 | 单位 | 币制 | 单价 | 总价 | 净重 | 毛重 | 原产国`

## 5. 策略模块详解

### 5.1 classifier.py — 品名归类

**核心逻辑**：
1. 按 `config.yaml` 的 `category_map` 关键词匹配，将细名替换为宽泛类别
2. 同时赋予对应的 HS 编码
3. 相同 (品名, HS编码) 的条目合并为一行，数值累加

**提单保护机制**（本次新增）：
- 调用 `set_bl_products()` 传入提单品名列表
- `_mark_bl_protected()` 对输入条目做三层英文名匹配（完整子串 → 去空格 → 关键词覆盖率≥50%且≥2词）
- 匹配成功：标记 `_bl_protected=True`，不改名、不合并（分组键使用 `id()` 保证独立性）
- 匹配失败：`_create_synthetic_item()` 创建兜底条目，自动推断材质（`_infer_material()`），剥离材质词到材质字段
- `cross_optimizer.py` 也检查 `_bl_protected` 标记，跳过受保护条目

### 5.2 cross_optimizer.py — 跨章HS优化

**核心逻辑**：
- 对每条商品，在全量 `tax_data` 中搜索税率更低的替代 HS 编码
- 计算品名相似度（bigram Jaccard + 字符重叠）
- 综合得分 = tax_score × tax_weight + similarity × similarity_weight
- 得分超过 `adopt_threshold` 即替换 HS 编码
- 白名单章节获得额外加成

### 5.3 devaluation.py — 低申报策略

- `price_multiplier`：统一将单价乘以该系数
- `total_cap`：所有条目总价不得超过此金额
- 两组预设参数分别对应 conservative/aggressive 模式

### 5.4 bl_parser.py — 提单品名提取

**核心逻辑**（从 PDF 提取）：
1. PyPDF2 提取文本
2. 按行分割，字母-数字粘连处用正则拆开
3. 过滤噪音（公司名、地址、电话、集装箱号等）
4. `_is_product_name()` 三重校验：必须含大写字母 + 至少一个产品特征词 + 不以数字开头
5. `PRODUCT_FEATURES` 集合内置了 80+ 常见产品特征词（coaster, phone, stand, bag, toy, light...）

## 6. config.yaml 结构

```yaml
classifier:
  mode: keyword
  category_map:        # 品名→类别+HS 对照表
    "关键词1":
      category: "宽泛类别名"
      hs: "XXXXXXXXXX"
  merge:
    enabled: true
    group_by: ["中文品名", "商品编码"]   # 合并分组键
    sum_fields: ["数量", "净重", "毛重", "箱数", "总价"]

cross_optimizer:
  min_similarity: 0.10
  adopt_threshold: 0.65
  tax_weight: 0.5
  similarity_weight: 0.5

devaluation:           # conservative 模式
  price_multiplier: 0.12
  total_cap: 12000

aggressive:            # aggressive 覆盖层
  devaluation:
    price_multiplier: 0.05
    total_cap: 8000
```

两种模式通过 `_resolve_mode_config()` 合并：aggressive 在 base 配置上叠加 aggressive 键覆盖。

## 7. FieldMapper 匹配策略

`backend/app/services/mapper.py` 负责将输入 Excel 任意列名映射到 14 个标准字段。

### 匹配算法 (`_match_single`)

| 情况 | 得分 |
|------|------|
| 完全匹配 | 1.0 |
| 清除换行后完全匹配 | 1.0 |
| CJK 前缀 + 英文后缀（如 "英文品名DESCRIPTION OF GOODS" → "英文品名"） | 0.85 |
| CJK 后缀 + 英文前缀 | 0.85 |
| English 前缀/后缀 | 0.9 |
| 子串匹配 | 0.4 + ratio × 0.3 |

最小通过分数：`FALLBACK_MIN_SCORE = 0.55`

### 关键修复（2026-04-29）

- **CJK 前缀匹配优先**：原本子串匹配先于前缀触发，导致 "英文品名DESCRIPTION OF GOODS" 仅得 0.436 被过滤。改为前缀优先后得 0.85 通过。
- **扩展关键词**：总价新增 `申报金额`/`清关申报金额`，材质新增 `中英文材质`，用途新增 `中英文用途`，净重新增 `实重`，毛重新增 `总抛重`。
- **原产国默认值**：从 "中国" 改为 "CN"。

## 8. 提单保护完整数据流

```
用户上传 (前端 BPipeline.tsx)
  ├── 清单文件 (.xlsx)  → formData["file"]
  └── 提单文件 (.pdf)   → formData["bl_file"]
       │
       ▼
app.py  /process 端点
  ├── 保存文件到临时目录
  ├── BLParser.parse_pdf(bl_file) → ["SILICONE COASTER", "PLASTIC MOBILE PHONE STAND"]
  │
       ▼
pipeline.py  run_pipeline(input_path, output_path, mode_cfg, bl_products=[...])
  │
  ├── [2/7] FieldMapper.map_fields() → items (14字段)
  │
  ├── [4/7] classifier.set_bl_products(bl_products)
  │         classifier.classify(items)
  │           ├── _mark_bl_protected() → 三层英文匹配
  │           │   ├── 匹配成功 → _bl_protected=True（不改名/不合并）
  │           │   └── 匹配失败 → _create_synthetic_item()（材质推断+品名清洗）
  │           ├── 关键词改名+HS赋值（跳过 _bl_protected 项）
  │           └── _merge_similar()（_bl_protected 项独立成组）
  │
  ├── [5/7] cross_optimizer.optimize()（跳过 _bl_protected 项）
  │
  └── [7/7] FileGenerator.generate() → 清关_{timestamp}.xlsx
```

## 9. 前端 BPipeline 页面

`frontend/src/pages/BPipeline.tsx` (+ `components/FileUpload.tsx`)

- **双上传区域**：左侧清单（Excel），右侧提单（PDF），两者缺一不可
- FileUpload 组件已重构为通用组件，接受 `accept`（扩展名+MIME类型）、`hint`、`maxSizeMB` 等 props
- 两个文件均上传后，"开始流水线"按钮才可用
- 进度条模拟 6 步流程（解析→映射→查税→归类→优化→生成）

## 10. 已知注意事项

1. **category_map 扩展**：当前 98 条关键词主要覆盖 example02 的品类。处理新客户清单时，需扩展 category_map 以减少 "未匹配" 品名。
2. **合成条目**：B/L 保护创建的兜底条目，HS 编码为空（因 category_map 关键词为中文，无法匹配英文品名）。如需自动赋 HS，需要在 config 中增加英文关键词。
3. **税率爬虫**：`use_crawler=true` 时 Step 3 需耗时较长（每条 HS 编码需要网络查询）。快速测试建议用 `use_crawler=false`。
4. **输出对比**：流水线输出与乙方手工参考文档存在差异是自然的——我们的输出是算法批量生成的（基于 config 策略 + 输入原始数据），手工参考文档经过了人工逐行核对和调整。
