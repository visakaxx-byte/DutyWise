# 清关优化系统 - 开发文档

## 项目概述

### 1.1 项目背景

客户需要一个自动化系统，帮助降低进口清关税金。系统通过智能识别装箱单信息，查询税率数据库，自动选择低税率的HS编码，生成标准化的清关文件。

### 1.2 核心价值

- **降低税金成本**：自动选择最低税率的HS编码
- **提高效率**：自动化处理，减少人工操作
- **规范化输出**：统一的清关文件格式
- **可追溯**：完整的操作日志，方便审计和反馈

### 1.3 业务流程

```
用户上传文档（一"票"2-3个Excel文件）
    ↓
系统智能识别字段
    ↓
提取商品信息
    ↓
查询税率数据库（codeflagai.com）
    ↓
智能优化HS编码（选择低税率）
    ↓
验证约束条件（重量、体积、品类相似度）
    ↓
生成清关文件（清关.xlsx）
    ↓
生成操作日志（替换记录、冲突记录）
    ↓
用户下载结果
```

### 1.4 核心概念

#### "票"（Shipment）
- 一批货物的完整信息
- 通常包含 2-3 个不同格式的文档
- 一次处理一"票"

#### HS编码（Harmonized System Code）
- 国际通用的商品分类编码
- 决定进口税率
- 同一商品可能有多个HS编码选择

#### 清关文件
- 标准化的报关文档
- 基于 `清关.xlsx` 模板
- 包含商品明细和必要信息

## 1.5 技术栈选择

### 后端
- **语言**：Python 3.10+
- **框架**：FastAPI（高性能、异步支持）
- **数据库**：PostgreSQL（存储历史记录）+ Redis（缓存税率数据）
- **任务队列**：Celery（处理耗时任务）

### 前端
- **框架**：React + TypeScript
- **UI库**：Ant Design
- **状态管理**：Zustand
- **文件上传**：react-dropzone

### 核心库
- **Excel处理**：openpyxl, pandas
- **爬虫**：playwright（支持JS渲染）
- **AI识别**：豆包大模型（字节跳动）
- **日志**：structlog
- **中文分词**：jieba

### 部署
- **容器化**：Docker + Docker Compose
- **Web服务器**：Nginx
- **进程管理**：Supervisor

## 1.8 开发原则

### 1.8.1 迭代开发
- **MVP优先**：先实现核心功能，快速验证
- **用户反馈驱动**：根据实际使用情况优化
- **小步快跑**：每个迭代周期 1-2 周

### 1.8.2 可维护性
- **模块化设计**：每个模块职责单一
- **完整日志**：所有操作可追溯
- **错误处理**：友好的错误提示

### 1.8.3 可扩展性
- **插件化**：字段映射规则可配置
- **缓存机制**：减少重复查询
- **异步处理**：支持大批量数据

## 1.9 关键假设和约束

### 假设
1. 输入文档主要是 Excel 格式（.xlsx, .xls）
2. 一"票"通常包含 2-3 个文档
3. 同一"票"的文档数据基本一致，冲突较少
4. 用户有基本的Excel操作能力

### 约束
1. 一次只处理一"票"
2. HS编码替换时，品类不能相差太远
3. 缺失字段留空，不强制补全
4. 所有操作需要记录日志

### 风险
1. **AI识别准确率**：字段映射可能不准确
2. **网站反爬虫**：税率查询可能被封
3. **数据质量**：输入文档格式差异大
4. **品类判断**：相似度判断可能不准确
